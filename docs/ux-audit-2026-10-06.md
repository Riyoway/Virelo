# Streaming UI / playback audit — 2026-10-06

## Scope and decisions

Both the npm player and the browser-only web player were reviewed. The landing page was not changed.
The UI stays content-first: no persistent play/pause badges over Shorts, one action rail for the active clip,
audio above Like, flat seek tracks, and contained field focus. Keyboard focus remains visible.

## Fixed findings

- Shorts: removed on-video playback buttons and central pause badge; tap and Space/Enter/K toggle playback.
- Shorts: audio moved above Like; inactive clips no longer contribute tabbable action rails.
- Shorts: per-visit random seed, stable pagination without duplicates or reshuffling on likes/progress.
- Shorts: resize/orientation changes keep the selected clip aligned. Compact landscape controls stay on screen.
- Shorts: cancelled autoplay and PiP callbacks do not restart an inactive clip. Long-press ignores seek controls.
- Player: user intent is separate from temporary pauses for audio/quality source changes. Latest intent wins.
- Player: paused seeking, delayed probes, and quality preparation do not unexpectedly resume playback.
- Player: buffering timers stop on pause; status overlays appear only when playback is actually waiting.
- Player: HLS position restoration listens for seek completion, not just metadata/canplay.
- Player: native-HLS switches cancel old restoration listeners; stale preparation results cannot alter a new item.
- Player: audible autoplay rejection retries muted, with a visible Unmute control, rather than a frozen first frame.
- Queue: selected media ID survives a query refresh instead of jumping back to the route's original item.
- Context menu: portal events cannot reopen the parent card's menu or trigger its navigation.
- Context menu: arrows/Home/End/Escape/Tab work; focus returns to the originating card/video.
- Metadata: Settings → Metadata has Clear all metadata with confirmation, across every added library (including hidden libraries). No per-video clear button. Filename/year are restored and matched text/artwork references removed.
- Metadata: npm records an automatic-match opt-out; explicit Fetch metadata opts back in after a successful match.
- Metadata: revision checks reject an in-flight match from before Clear. Artwork URLs are revisioned to avoid stale images.
- Browser-only library: progress, favorites and metadata resets update atomically in IndexedDB.
- Browser-only library: thumbnail/object-URL cleanup no longer discards the selected File during scanning.
- Missing video and Shorts load failures provide an error/retry state instead of an endless skeleton or misleading empty state.

## Repeatable browser audits

The npm repository includes `scripts/audit-ui.mjs` and `scripts/audit-playback.mjs`.
They require FFmpeg and a Node-resolvable Playwright installation with Chromium; no new runtime dependencies were added.

Start npm's Vite server on 5198 and the web repository's Vite server on 5199, then run:

```text
node scripts/audit-ui.mjs
npm run build
node scripts/audit-playback.mjs
```

Optional environment variables: `VIRELO_TEST_NPM_URL`, `VIRELO_TEST_WEB_URL`,
`VIRELO_TEST_NODE_PACKAGE` (package.json used to resolve Playwright), `VIRELO_TEST_CHROMIUM`, `FFMPEG_PATH`.
The scripts use isolated fixtures/databases, close their own browser/server, and leave diagnostics in temporary
directories printed in their output. The real-playback harness disables autoplay restrictions to isolate decoding;
the separate default-policy check was also performed during this audit.

## Limits / follow-up checks

- Automated Chromium checks are not a physical iPhone/Android, Safari native-HLS, or Firefox certification.
- Remote mode used a loopback address plus simulated buffering, not an actual congested Wi-Fi connection.
- Audio verification measured decoding and synchronization; it was not a manual speaker/headphone listening test.
- Browser-only conversion speed/memory and codec support depend on browser, file size, and hardware.
- The web build still warns about the large media-codec WatchView chunk (~2.68 MB before gzip); lazy codec loading
  is a follow-up performance opportunity, not addressed by this UI/state fix.
- Clearing metadata preserves the video, generated thumbnail, likes and progress. Shared downloaded artwork cache
  files are not deleted, since another title may use them.
- No npm publish, version bump, or push was performed for this request.
